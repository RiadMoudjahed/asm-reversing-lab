# التمرين 15. المخزون المترابط

Level 4. الوقت: نحو 3 ساعات. المعمارية: x86-64 على Linux. الوحدات: [15. استعادة البيانات](../../modules/15-recovering-data/README.ar.md)

## السيناريو

أداة مستودع اسمها `inventory` تحتفظ بأرقام المخزون في بنية بيانات مترابطة في الذاكرة. أُزيلت رموزها وضاعت شيفرتها المصدرية. وتحتاج أداة ثانية مكتوبة بلغة التجميع إلى إضافة أرقام إلى البنية نفسها والبحث فيها، وتقرأ بيئة الاختبار العقد التي تبنيها شيفرتك، فيجب أن يطابق التخطيط تماماً. تستعيد أولاً تخطيط العقدة وقواعد الإدراج. ثم تكتب الدالتين.

## الأهداف

- التعرف على شجرة في شيفرة مترجمة: حجز الذاكرة وحقول العقدة والعبور.
- استعادة إزاحات الحقول وعروضها ومعانيها من التعليمات التي تستخدمها.
- كتابة شيفرة بنية البيانات نفسها بلغة التجميع، بما في ذلك الحالة التي يكون فيها الرابط ما يزال فارغاً.

## الجزء 1: Reverse

الملف التنفيذي هو `bin/inventory`. يقرأ أوامر من الدخل القياسي، أمراً في كل سطر.

</div>

```bash
printf 'i 5\ni 9\ni 5\nf 5\nf 7\nd\n' | bin/inventory
objdump -d -M intel bin/inventory
```

<div dir="rtl">

يخزّن الأمر `i KEY` مفتاحاً (عدداً صحيحاً بإشارة من 32 بتاً) ويطبع `ok`. ويطبع الأمر `f KEY` عددين لمفتاح مخزَّن، أو `none`. ويطبع الأمر `d` البنية كلها نصاً. يحجز البرنامج كتلة ذاكرة لكل عقدة، وتحوي كل العقد الحقول نفسها.

أوجد هذه القيم الست:

1. `S`: الحجم بالبايتات الذي يطلبه البرنامج لعقدة واحدة، بالعشري.
2. `K`: إزاحة المفتاح داخل العقدة بالبايتات، بالعشري.
3. `T`: إزاحة العداد ذي 32 بتاً الذي يزداد مع كل أمر `i` يمر عبوره بالعقدة، بالبايتات وبالعشري.
4. `C`: إزاحة العداد الذي يزداد فقط عندما يُخزَّن المفتاح نفسه مرة أخرى، بالبايتات وبالعشري.
5. `G`: إزاحة المؤشر الذي يتبعه العبور عندما يكون المفتاح الجديد أكبر من مفتاح العقدة، بالبايتات وبالعشري.
6. `W`: أول عدد يطبعه `f 7` بعد إعطاء الأمر `i 7` مرات متتالية عددها 65540، بالعشري.

</div>

```bash
for i in $(seq 65540); do echo 'i 7'; done | { cat; echo 'f 7'; } | bin/inventory | tail -1
```

```text
ARL{inventory_<S>_<K>_<T>_<C>_<G>_<W>}
```

<div dir="rtl">

فمثلاً القيم 40 و8 و12 و16 و24 و3 تعطي `ARL{inventory_40_8_12_16_24_3}`.

## الجزء 2: Assemble

عدّل `starter/solution.asm` لتنفيذ دالتين وفق اصطلاح استدعاء System V:

</div>

```c
struct node *inv_insert(struct node *root, int key);
struct node *inv_find(struct node *root, int key);

/* Provided by the tests. */
struct node *inv_alloc(void);
```

<div dir="rtl">

- تفعل `inv_insert` ما يفعله الأمر `i` في `bin/inventory`. و`root` هو المؤشر إلى العقدة الأولى، أو 0 لبنية فارغة. وتعيد المؤشر إلى العقدة الأولى بعد الإدراج. ويجب أن يطابق كل تغيير يجريه البرنامج على العقد الموجودة وكل حقل في عقدة جديدة.
- تعيد `inv_find` المؤشر إلى العقدة التي تحوي `key`، أو 0 إن لم توجد.
- تعيد `inv_alloc` كتلة ذاكرة بحجم العقدة الذي وجدته، مملوءة بالأصفار. استدعها مرة واحدة لكل عقدة جديدة ولا تستدعها في غير ذلك.

تبدأ الاختبارات ببنية فارغة وتنفذ سلسلة من الإدراجات وعمليات البحث وتطبع ما تقرؤه المكتبة من عقدك. وتقارن كل سطر بالخرج الذي ينتجه `bin/inventory` للأوامر نفسها.

## القواعد

- استخدم تخطيط البرنامج وقواعده؛ فالاختبارات تقرأ عقدك من خلالها.
- اكتب في حقول العقد فقط. وتتحقق الاختبارات من أن شيئاً لا يتغير بعد حجم العقدة وأن البايتات غير المستخدمة داخل العقدة تبقى أصفاراً.
- احفظ السجلات التي يجب أن تحفظها الدالة المستدعاة `rbx` و`rbp` و`r12` إلى `r15`.
- أبقِ المكدس محاذياً عند كل `call`.
- لا تستدعِ شيئاً غير `inv_alloc`.
