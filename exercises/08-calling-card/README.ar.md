# التمرين 08. بطاقة التعريف

Level 3. الوقت: نحو 3 ساعات. المعمارية: x86 وx86-64 على Linux. الوحدات: [08. المكدس والإجراءات واصطلاحات الاستدعاء](../../modules/08-stack-and-calls/README.ar.md)

## السيناريو

سلّم مورّد برنامجَي اختبار صغيرين، `callcard32` و`callcard64`، مع ملف ترويسة ضاع. كانت الترويسة تذكر اصطلاح الاستدعاء لكل دالة، وعلى فريق التكامل الآن أن يستدعي هذه الدوال من شيفرة أخرى. وبدون الترويسة يجب قراءة الاصطلاح من شيفرة الآلة. ثم يجب كتابة بديل لثلاث من الدوال، بالاصطلاحات نفسها، كي تستمر المستدعيات الحالية في العمل.

## الأهداف

- التمييز بين cdecl وstdcall وfastcall في شيفرة 32 بت من طريقة قراءة الوسائط وطريقة تنظيف المكدس بعد الاستدعاء.
- التمييز بين System V AMD64 وMicrosoft x64 في شيفرة 64 بت من سجلات الوسائط ومساحة الظل (shadow space) وتعديل المستدعي للمكدس.
- كتابة دوال يطابق أثرها على المكدس اصطلاحها، بحيث يبقى المستدعي المكتوب لذلك الاصطلاح متوازناً.

## الجزء 1: Reverse

الملفان التنفيذيان هما `bin/callcard32` (32 بت) و`bin/callcard64` (64 بت). يشغّل كل منهما اختباراً ذاتياً لدوالّه ويطبع `callcard32: ok` أو `callcard64: ok`. والدوال هي الرموز العامة من `f1` إلى `f4` في `callcard32` و`g1` و`g2` في `callcard64`.

</div>

```bash
bin/callcard32
bin/callcard64
objdump -d -M intel bin/callcard32
objdump -d -M intel bin/callcard64
```

<div dir="rtl">

تستخدم كل دالة واحداً من خمسة اصطلاحات. أسند حرفاً إلى كل دالة:

| الحرف | الاصطلاح |
|---|---|
| `c` | cdecl: الوسائط على المكدس، ويزيلها المستدعي |
| `s` | stdcall: الوسائط على المكدس، وتزيلها الدالة المستدعاة |
| `f` | fastcall (32 بت): أول وسيطين في `ecx` و`edx`، والباقي على المكدس، وتزيل الدالة المستدعاة هذا الباقي |
| `v` | System V AMD64: الوسائط الأولى في `rdi` و`rsi` و`rdx` و`rcx` و`r8` و`r9` |
| `m` | Microsoft x64: الوسائط الأولى في `rcx` و`rdx` و`r8` و`r9`، مع 32 بايت من مساحة الظل |

ابنِ العلم من الأحرف الستة، بترتيب `f1` و`f2` و`f3` و`f4` و`g1` و`g2`:

</div>

```text
ARL{calling_<f1><f2><f3><f4><g1><g2>}
```

<div dir="rtl">

فمثلاً إذا كانت الأحرف `c` و`c` و`s` و`f` و`v` و`m`، يكون العلم `ARL{calling_ccsfvm}`.

## الجزء 2: Assemble

عدّل `starter/solution.asm` لتنفيذ ثلاث دوال في شيفرة 32 بت. يجب أن تحسب كل منها النتيجة نفسها التي تحسبها الدالة التي في الموضع نفسه من الجزء 1، وأن تستخدم اصطلاح الاستدعاء نفسه:

- `cc_f1` تطابق `f1`.
- `cc_f2` تطابق `f2`.
- `cc_f3` تطابق `f3`.

تأخذ الثلاث ثلاثة وسائط من النوع `int` وتعيد `int`. وتستدعيها الاختبارات عبر نماذج أولية تصرّح باصطلاح كل منها:

</div>

```c
int __attribute__((stdcall))  cc_f1(int a, int b, int c);
int                           cc_f2(int a, int b, int c);   /* cdecl */
int __attribute__((fastcall)) cc_f3(int a, int b, int c);
```

<div dir="rtl">

اقرأ صيغة كل دالة من شيفرتها في `callcard32`، ولاحظ أي وسيط يقع في أي موضع.

## القواعد

- يقارن برنامج الاختبار مؤشر المكدس قبل كل استدعاء وبعده. الدالة التي تزيل بايتات أقل من اللازم أو أكثر منه تفشل، حتى لو كانت نتيجتها صحيحة.
- احفظ `ebx` و`esi` و`edi` و`ebp`.
- لا تستخدم `call`.
- تلتف النتائج عند 32 بت؛ وتتضمن الاختبارات قيماً كبيرة جداً وصغيرة جداً.
