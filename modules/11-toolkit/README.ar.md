# 11. صندوق أدوات من يمارس الهندسة العكسية

الوقت: نحو 3 ساعات. المتطلبات السابقة: [10. أساسيات أنظمة التشغيل لمن يمارس الهندسة العكسية](../10-os-for-reversers/README.ar.md)

## لماذا يهم هذا

لا ينجح سير العمل في الوحدة 09 إلا إذا استطعت تنفيذ كل خطوة بسرعة. تقدم هذه الوحدة الأدوات بالترتيب الذي تستخدمه به: تحديد هوية الملف، وقراءة بنيته، وتفكيكه، واستكشافه تفاعلياً، وتشغيله تحت مصحح أخطاء، ومراقبته من الخارج. وتستخدم برنامجاً صغيراً مبنياً من `examples/11_target.c` لتتمكن من مقارنة ما تعرضه كل أداة عن الشيفرة نفسها.

## المفاهيم

### برنامج التدريب

يأخذ `11_target` كلمة واحدة وسيطاً، ويطبع رقماً محسوباً منها، ويطبع `access granted` لكلمة بعينها و`denied` لأي كلمة أخرى. ابنه وشغّله:

</div>

```bash
make
build/11_target hello
build/11_target open-sesame
```

```text
score 99162322
denied
score -1484336485
access granted
```

<div dir="rtl">

تُنفَّذ أوامر هذه الوحدة من `modules/11-toolkit/examples`. البرنامج بسيط عمداً: يحوي حلقة (`score`) ومقارنة (`check`) واستدعاء مكتبة (`strcmp`).

### الخطوة 1: تحديد هوية الملف

يقرأ `file` الترويسات ويقول ما هو الملف:

</div>

```bash
file build/11_target
```

```text
build/11_target: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=3690f8d5a33ef0140c7ee95bff861bc16fb6e86b, for GNU/Linux 3.2.0, not stripped
```

<div dir="rtl">

يطبع `strings` تسلسلات الأحرف القابلة للطباعة. ويضيف `-t x` إزاحة الملف بالست عشري، ويحدد `-n` الحد الأدنى للطول:

</div>

```bash
strings -t x -n 6 build/11_target | grep sesame
```

```text
   2038 open-sesame
```

<div dir="rtl">

يعرض `xxd` البايتات الخام. وهذه بداية ترويسة ELF:

</div>

```bash
xxd -l 32 build/11_target
```

```text
00000000: 7f45 4c46 0201 0100 0000 0000 0000 0000  .ELF............
00000010: 0200 3e00 0100 0000 7010 4000 0000 0000  ..>.....p.@.....
```

<div dir="rtl">

البايتات الأربعة الأولى `7f 45 4c 46` هي الرقم السحري (`.ELF`). البايت 4 يساوي `02` لـ 64 بت، والبايت 5 يساوي `01` لـ little-endian. عند الإزاحة 0x10 النوع `02 00` (ملف تنفيذي) والآلة `3e 00` (x86-64). وعند الإزاحة 0x18 نقطة الدخول بطول 8 بايتات `70 10 40 00 00 00 00 00` أي العنوان 0x401070. وتشرح الوحدة 12 كل حقل.

### الخطوة 2: قراءة البنية

يطبع `readelf` بنية الملف دون تفسير الشيفرة:

</div>

```bash
readelf -h build/11_target | grep -E "Class|Type|Machine|Entry"
readelf -d build/11_target | grep NEEDED
readelf -S -W build/11_target | grep -E " \.(text|rodata|data|bss|got)"
readelf -s build/11_target | grep -E "FUNC.*(score|check|main)"
```

```text

  Type:                              EXEC (Executable file)
  Machine:                           Advanced Micro Devices X86-64
  Entry point address:               0x401070
 0x0000000000000001 (NEEDED)             Shared library: [libc.so.6]

  [16] .rodata           PROGBITS        0000000000402000 002000 000044 00   A  0   0  8
```

<div dir="rtl">

تدلك الأقسام على مواضع الشيفرة (`.text`، الرايتان `AX`: مخصص وقابل للتنفيذ) والثوابت (`.rodata`، `A`) والبيانات (`.data` و`.bss`، الرايتان `WA`: قابل للكتابة). ويعطي جدول الرموز عنوان كل دالة وحجمها. أما الملف التنفيذي المجرَّد (stripped) فلا أسماء دوال فيه؛ وتعيد اكتشافها بنفسك.

### الخطوة 3: التفكيك

يفكك `objdump -d` الأقسام القابلة للتنفيذ. ويطبع صيغة AT&T افتراضياً وصيغة Intel مع `-M intel`. يستخدم هذا المقرر صيغة Intel، لكن مخرجات المترجمات وكثيراً من الأدوات تستخدم AT&T افتراضياً، فيجب أن تقرأ الصيغتين.

</div>

```bash
objdump -d -M intel --no-show-raw-insn build/11_target | awk '/<check>:/{p=1} p{print} /^$/{if(p)exit}'
objdump -d --no-show-raw-insn build/11_target | awk '/<check>:/{p=1} p{print} /^$/{if(p)exit}'
```

```text
0000000000401184 <check>:
  401184:    sub    rsp,0x8
  401188:    lea    rsi,[rip+0xea9]        # 402038 <secret>
  40118f:    call   401040 <strcmp@plt>
  401194:    test   eax,eax
  401196:    sete   al
  401199:    movzx  eax,al
  40119c:    add    rsp,0x8
  4011a0:    ret
```

```text
0000000000401184 <check>:
  401184:    sub    $0x8,%rsp
  401188:    lea    0xea9(%rip),%rsi        # 402038 <secret>
  40118f:    call   401040 <strcmp@plt>
  401194:    test   %eax,%eax
  401196:    sete   %al
  401199:    movzbl %al,%eax
  40119c:    add    $0x8,%rsp
  4011a0:    ret
```

<div dir="rtl">

قراءة الدالة: تحمّل عنوان `secret` في `rsi` (الوسيط الثاني)، وتستدعي `strcmp` (الوسيط الأول في `rdi` أصلاً)، ثم تحوّل «النتيجة تساوي صفراً» إلى 0 أو 1 في `eax`. وتعيد الدالة هل السلسلتان متساويتان.

#### قراءة صيغة AT&T

| | Intel | AT&T |
|---|---|---|
| ترتيب المعاملات | الوجهة، المصدر | المصدر، الوجهة |
| السجلات | `eax` | `%eax` |
| الثوابت | `0x8` | `$0x8` |
| الذاكرة | `[rsi + rcx*4 + 8]` | `8(%rsi,%rcx,4)` |
| حجم المعامل | في المعامل: `dword ptr [rax]` | في لاحقة الاختصار: `movl` و`movq` و`movzbl` |
| مثال | `movzx eax, al` | `movzbl %al, %eax` |

للتحويل اعكس المعاملات وأزل الزخارف. وحروف اللواحق هي `b` (بايت) و`w` (كلمة) و`l` (كلمة مزدوجة) و`q` (كلمة رباعية). في `movzbl` يعني الحرفان «من بايت إلى long».

### الخطوة 4: الاستكشاف التفاعلي بـ Rizin

Rizin مفكك تجميع وإطار تحليل بسطر الأوامر. يحلل `-A` الملف عند التحميل، ويخرج `-q` بعد الأوامر، وينفذها `-c`.

</div>

```bash
rizin -q -e scr.color=0 -A -c "pdf @ sym.check" build/11_target
```

```text
            ; CALL XREF from main @ 0x4011cf
┌ sym.check(const char *s1);
│           ; arg const char *s1 @ rdi
│           0x00401184      sub   rsp, 0x08
│           0x00401188      lea   rsi, qword obj.secret                ; 0x402038 ; "open-sesame" ; const char *s2
│           0x0040118f      call  sym.imp.strcmp                       ; int strcmp(const char *s1, const char *s2)
│           0x00401194      test  eax, eax
│           0x00401196      setz  al
│           0x00401199      movzx eax, al
│           0x0040119c      add   rsp, 0x08
└           0x004011a0      ret
```

<div dir="rtl">

فعل Rizin أكثر من `objdump`: سمّى الوسيط، وحلّ إحالة البيانات إلى السلسلة، وأظهر النموذج الأولي لـ `strcmp`. وأكثر الأوامر استخداماً:

| الأمر | المعنى |
|---|---|
| `aaa` | يحلل كل شيء (الخيار `-A` يفعل ذلك عند التحميل) |
| `afl` | يعرض الدوال التي عُثر عليها |
| `pdf @ sym.check` | يطبع تفكيك دالة |
| `axt @ sym.check` | يعرض الإحالات المتقاطعة إلى `sym.check` (من يستدعيها) |
| `iz` | يعرض السلاسل في أقسام البيانات |
| `s 0x401184` | ينتقل إلى عنوان |
| `?` | مساعدة لأي أمر؛ أضف `?` إلى بادئة مثل `a?` |

</div>

```bash
rizin -q -e scr.color=0 -A -c "axt @ sym.check; iz~sesame" build/11_target
```

```text
main 0x4011cf [CALL] call sym.check
0x00002038 0x00402038  11   12 .rodata ascii open-sesame
```

<div dir="rtl">

يقول السطر الأول إن `main` تستدعي `check` عند 0x4011cf. ويقول الثاني إن السلسلة عند إزاحة الملف 0x2038 والعنوان الافتراضي 0x402038، بما يطابق `strings -t x`.

### الخطوة 5: Ghidra

Ghidra مجموعة رسومية فيها مفكك تجميع ومفكك ترجمة. ثبّتها على جهازك في الوحدة 00. وهذا سير العمل؛ وهو نفسه لكل ملف تنفيذي في المقرر.

1. أنشئ مشروعاً، واستورد الملف التنفيذي من `exercises/NN-name/bin/` وقبل الصيغة المكتشفة.
2. افتح الملف في متصفح الشيفرة ودع التحليل الافتراضي يعمل.
3. انظر في شجرة الرموز عن الدوال، وفي نافذة السلاسل المعرَّفة (Defined Strings) عن السلاسل. انقر مرتين على سلسلة، ثم انظر إلى إحالاتها المتقاطعة لتجد الشيفرة التي تستخدمها.
4. اقرأ القائمة (التفكيك) ومفكك الترجمة جنباً إلى جنب. مفكك الترجمة تقريبي، فقارنه بالتعليمات عندما يبدو شيء خاطئاً.
5. حسّن البرنامج كلما تعلمت. أعد تسمية الدوال والمتغيرات (المفتاح الافتراضي `L`)، وغيّر الأنواع (المفتاح الافتراضي `Ctrl+L` على متغير)، وأضف تعليقات (المفتاح الافتراضي `;`). واعرض الإحالات المتقاطعة لعنصر بالمفتاح الافتراضي `X`.

فائدة إعادة التسمية وإعادة تحديد الأنواع أن مفكك الترجمة يعيد رسم مخرجاته بأسمائك وأنواعك، فتجعل كل خطوة الدالة التالية أسهل قراءة. وقد تختلف اختصارات لوحة المفاتيح بين إصدارات Ghidra وإعداداتها؛ وتسرد قائمتا Edit وNavigation الاختصارات الحالية.

### الخطوة 6: التشغيل تحت مصحح أخطاء

يشغّل GDB البرنامج تحت تحكمك. تحمّل صورة المختبر GEF، وهي إضافة تطبع السجلات والمكدس والشيفرة حول `rip` عند كل توقف. وتعطّل الصيغة الدفعية أدناه الإضافات (`-nx`) ليكون الخرج نصاً عادياً؛ وفي المختبر ستستخدم عادةً الصيغة التفاعلية.

</div>

```bash
gdb -nx -q -batch -ex "break check" -ex "run hello" -ex "info registers rdi" \
    -ex "x/s \$rdi" -ex "x/s 0x402038" -ex "finish" -ex "print \$rax" build/11_target
```

```text
Breakpoint 1, 0x0000000000401184 in check ()
rdi            0x7fffd18f3e21      140736709213729
0x7fffd18f3e21:    "hello"
0x402038 <secret>:    "open-sesame"
0x00000000004011d4 in main ()
$1 = 0
```

<div dir="rtl">

عند نقطة التوقف يشير `rdi` إلى سلسلة الوسيط، وهي «hello». ويطبع `x/s` الثاني السلسلة التي يقارنها `check` بها. وبعد `finish` تكون `check` قد عادت إلى `main` وتكون `rax` تساوي 0، أي حالة «denied». والعنوان في `rdi` على المكدس ويتغير من تشغيل إلى آخر.

| الأمر | المعنى |
|---|---|
| `break check` or `b *0x401184` | يتوقف عند دالة أو عند عنوان محدد |
| `run ARGS` | يبدأ البرنامج بوسائط |
| `continue` | يستأنف |
| `stepi`, `nexti` | ينفذ تعليمة واحدة، بالدخول في الاستدعاءات أو تجاوزها |
| `finish` | ينفذ حتى تعود الدالة الحالية |
| `info registers` | يعرض السجلات؛ أضف أسماء لعرض هذه فقط |
| `x/NFU ADDR` | يفحص الذاكرة: `N` وحدة بصيغة `F` وحجم `U`، مثل `x/4gx $rsp` و`x/s $rdi` و`x/5i $pc` |
| `watch EXPR` | يتوقف عندما تتغير قيمة |
| `set disassembly-flavor intel` | يعرض صيغة Intel (تضبطها صورة المختبر) |

جلسة ثانية تسير في حلقة `score`:

</div>

```bash
gdb -nx -q -batch -ex "break score" -ex "run ab" -ex "x/i \$pc" -ex "stepi 3" \
    -ex "x/i \$pc" -ex "info registers eax ecx" build/11_target
```

```text
Breakpoint 1, 0x0000000000401156 in score ()
=> 0x401156 <score>:    movzbl (%rdi),%eax
0x000000000040115d in score ()
=> 0x40115d <score+7>:    mov    $0x0,%ecx
eax            0x61                97
ecx            0x403e00            4210176
```

<div dir="rtl">

حُمِّل الحرف الأول من «ab»: `eax` تساوي 0x61، وهي «a». وقيمة `ecx` هي ما كان في السجل قبل أن تهيئه الشيفرة، وهذا يحدث عند 0x40115d. ويطبع GDB هنا صيغة AT&T لأن الإضافات كانت معطلة؛ وتحوّلها إعدادات صورة المختبر إلى Intel.

### الخطوة 7: المراقبة من الخارج

`strace` و`ltrace`، اللذان قُدّما في الوحدة 10، أسرع أدوات المراقبة:

</div>

```bash
strace -e trace=write build/11_target hello
ltrace build/11_target hello
```

```text
write(1, "score 99162322\ndenied\n", 22score 99162322
denied
) = 22
+++ exited with 1 +++
```

```text
__printf_chk(2, 0x402014, 0x5e918d2, 0x5e918d2)  = 15
strcmp("hello", "open-sesame")                   = -7
puts("denied")                                   = 7
score 99162322
denied
+++ exited (status 1) +++
```

<div dir="rtl">

يكشف `ltrace` وسيط `strcmp` مباشرة، وهو غالباً أسرع طريقة لمعرفة ما يقارن به البرنامج مدخله. الاستدعاء الأول هو `printf` مترجمة إلى `__printf_chk`؛ والوسيط الثاني مؤشر إلى سلسلة التنسيق، والآخران هما الرقم المطبوع (0x5e918d2 تساوي 99162322).

### اختيار أداة

| السؤال | ابدأ بـ |
|---|---|
| ما نوع هذا الملف؟ | `file`, `xxd` |
| ما النص الذي يحويه؟ | `strings -t x` |
| ما الأقسام والرموز والمكتبات؟ | `readelf` |
| ماذا تفعل التعليمات؟ | `objdump`, Rizin, Ghidra |
| من يستدعي هذه الدالة أو يستخدم هذه السلسلة؟ | `axt` في Rizin، والإحالات المتقاطعة في Ghidra |
| ما القيم الفعلية وقت التشغيل؟ | GDB |
| ماذا يفعل من الخارج؟ | `strace`, `ltrace` |

## جرّبه

1. دون تشغيل البرنامج بالكلمة الصحيحة، اعثر على الكلمة التي يتوقعها باستخدام أدوات ساكنة فقط. استخدم `strings` ثم أكّد بـ `rizin` بمعرفة ما يقارن به `check`.
2. باستخدام GDB توقف عند `score` بالوسيط `abc` وسِر في الحلقة حتى تحمل `ecx` النتيجة النهائية. قارنها بالرقم الذي يطبعه البرنامج.
3. حوّل قائمة AT&T لـ `check` على الورق إلى صيغة Intel، ثم قارنها بقائمة Intel.
4. باستخدام `ltrace` اعرف أي دالة تستدعيها `main` لطباعة النتيجة.

## أخطاء شائعة

- **قراءة AT&T كأنها Intel.** ترتيب المعاملات معكوس. تحقق من الصيغة قبل القراءة.
- **اعتبار `strings` الصورة الكاملة.** السلاسل التي تُبنى أو تُفك وقت التشغيل ليست في الملف.
- **تصديق مفكك الترجمة.** إنه إعادة بناء. قارنه بالتعليمات.
- **نسيان أن التحليل تخمين.** قد يفوّت التحليل الآلي دوال أو يصنّف بيانات على أنها شيفرة. تحقق من حدود الدوال عندما تبدو النتيجة غريبة.
- **التوقف في المكان الخاطئ.** نقطة توقف على اسم دالة تتوقف عند أول تعليمة؛ الوسائط في السجلات أصلاً، لكن المتغيرات المحلية لم تُهيأ بعد.

## الخلاصة

- حدّد هوية الملف بـ `file` و`strings` و`xxd`؛ واقرأ بنيته بـ `readelf`.
- فكّك بـ `objdump` أو Rizin أو Ghidra؛ وأتقن صيغتي Intel وAT&T.
- يوفر Rizin تحليلاً تفاعلياً من سطر الأوامر؛ ويضيف Ghidra مفكك ترجمة ويتيح إعادة التسمية وتغيير الأنواع والتعليق.
- يعرض GDB القيم الفعلية: ضع نقاط توقف، وسِر خطوة خطوة، وافحص السجلات والذاكرة.
- يعرض `strace` و`ltrace` استدعاءات النظام والمكتبات في البرنامج دون قراءة الشيفرة.
