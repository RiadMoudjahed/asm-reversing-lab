# 00. إعداد المختبر

الوقت: نحو 45 دقيقة. المتطلبات السابقة: لا شيء سوى أساسيات لغة C وحاسوب Linux أو macOS أو Windows قادر على تشغيل Docker.

## لماذا هذا مهم

تعمل كل أمثلة الدورة وتمارينها في بيئة واحدة معدّة مسبقاً، لتتطابق نتائجك مع النتائج الظاهرة في الدروس. عشر دقائق من الإعداد هنا توفر ساعات من عبارة "تعمل على جهازي فقط" لاحقاً.

بنهاية هذه الوحدة سيكون لديك مختبر يعمل، وسلسلة أدوات تم التحقق منها، وGhidra على جهازك المضيف، وصورة واضحة لكيفية تدقيق التمارين.

## المفاهيم

### طريقتان لتشغيل المختبر

**Docker (موصى به).** تحتوي صورة المختبر على كل الأدوات بإصدارات ثابتة. يُركَّب مجلد المستودع داخلها عند `/lab`، فتظهر فيها فوراً الملفات التي تعدّلها على جهازك.

</div>

```bash
make shell
```

<div dir="rtl">

يبني التشغيل الأول الصورة، وحجمها نحو 6.6 غيغابايت على القرص وتنزّل حزماً كثيرة، فخصّص وقتاً واتصالاً جيداً. تبدأ التشغيلات اللاحقة خلال ثوانٍ. داخل المختبر يظهر في موجّه الأوامر المستخدم `lab`، وتتوفر أوامر الدورة (`make check` و`nasm` و`gdb`).

**التثبيت المباشر (Ubuntu أو Debian).** إذا كنت تفضّل عدم استخدام Docker:

</div>

```bash
sudo scripts/install-native.sh
```

<div dir="rtl">

ثم ضع `NATIVE=1` قبل أوامر الدورة، مثلاً `make NATIVE=1 check EX=01`. يثبّت السكربت المجمّع (assembler) والمترجمات ومصحح الأخطاء ومكتبات Python نفسها الموجودة في الصورة. ولا يثبّت Rizin ولا Ghidra.

### ما يحتويه المختبر

| الأداة | الغرض |
|---|---|
| `nasm` | المجمّع: يحوّل شيفرة التجميع إلى ملف كائني |
| `ld` | الرابط: يحوّل الملفات الكائنية إلى ملف تنفيذي |
| `gcc`, `g++` | مترجما C وC++، ويُستخدمان أيضاً لربط شيفرة التجميع ببيئات اختبار C |
| `gdb` مع GEF | مصحح الأخطاء، مع عرض مقروء للسجلات والذاكرة |
| `objdump`, `readelf` | تفكيك الشيفرة وفحص بنية الملف التنفيذي |
| `rizin` | أداة تفكيك وإطار تحليل بسطر الأوامر |
| `strace`, `ltrace` | عرض استدعاءات النظام واستدعاءات المكتبات التي ينفذها البرنامج |
| `yara` | مطابقة الأنماط، وتُستخدم في وحدة تحليل البرمجيات الخبيثة |
| `mingw-w64`, `wine` | بناء برامج Windows وتشغيلها على Linux |
| Python 3 | يشغّل مدققات التمارين؛ ومكتبات لتحليل ملفات ELF وPE |

### Ghidra على جهازك المضيف

Ghidra حزمة رسومية للهندسة العكسية. هي كبيرة ورسومية أكثر مما يلائم صورة المختبر، لذا تثبّتها على جهازك وتفتح ملفات التحديات من مجلد المستودع.

1. نزّل Ghidra من صفحة الإصدارات الرسمية للمشروع.
2. ثبّت إصدار JDK الذي يطلبه ملف README الخاص بالإصدار.
3. فك ضغط Ghidra، وشغّله بسكربت التشغيل الخاص به، وأنشئ مشروعاً.
4. استورد الملفات التنفيذية من `exercises/NN-name/bin/` في مجلد المستودع.

ستبدأ استخدام Ghidra في الوحدة 11. تثبيته الآن يتيح لك المتابعة لاحقاً دون انقطاع.

### كيف تعمل التمارين والمدققات

يقع كل تمرين في `exercises/NN-name/` ويتكون من جزأين:

- **الجزء 1، Reverse.** تحلل البرنامج الموجود في `bin/` وتجيب عن أسئلة. تنتج الإجابات علماً (flag) بالصيغة `ARL{...}`.
- **الجزء 2، Assemble.** تعدّل `starter/solution.asm` ليستوفي مواصفات محددة.

للتحقق من عملك:

</div>

```bash
make check EX=01 ARGS='--flag ARL{your_answer_here}'
```

<div dir="rtl">

يعرض المدقق نتيجة كل جزء على حدة. ولا يُظهر العلم المتوقع أبداً: يخزّن المستودع فقط تجزئة مملّحة (salted hash) له. إذا فشل جزء، فاقرأ `HINTS.md` في مجلد التمرين. التلميحات مكتوبة بثلاثة مستويات؛ افتح مستوى واحداً في كل مرة.

يحتوي مجلد `solutions/` على الإجابات الكاملة. أبقِه مغلقاً حتى تنتهي أو تبذل محاولة جادة.

## جرّب بنفسك

شغّل المختبر ونفّذ اختبار التشغيل الأولي. يجمّع برنامجاً من أربع تعليمات، ويربطه، ويشغّله، ثم يتحقق من سلسلة الأدوات.

</div>

```bash
make shell
cd modules/00-setup/examples
make run
```

<div dir="rtl">

الناتج المتوقع:

</div>

```text
mkdir -p build
nasm -f elf64 00_exit42.asm -o build/00_exit42.o
ld build/00_exit42.o -o build/00_exit42
./build/00_exit42; echo "exit status: $?"
exit status: 42
bash check_tools.sh

ld         ok
gcc        ok
g++        ok
make       ok
gdb        ok
objdump    ok
readelf    ok
strace     ok
ltrace     ok
rizin      ok
yara       ok
python3    ok
xxd        ok
file       ok
gcc -m32   ok
```

<div dir="rtl">

يؤدي البرنامج في `00_exit42.asm` شيئاً واحداً: ينتهي بحالة خروج 42. لا تحتاج إلى فهمه الآن؛ توضح الوحدة 03 كل سطر فيه. المهم أن الخطوات الثلاث (التجميع والربط والتشغيل) نجحت، وهذا يثبت سلامة سلسلة الأدوات.

افتح الآن GDB مرة واحدة للتأكد من تحميل GEF:

</div>

```bash
gdb -q build/00_exit42
```

<div dir="rtl">

يجب أن يذكر السطر الأول من الناتج `GEF for linux ready`. اكتب `quit` للخروج.

## أخطاء شائعة

- **`permission denied` عند تشغيل Docker.** على Linux يجب أن يكون مستخدمك في مجموعة `docker`، أو أن تشغّل Docker بصلاحيات المسؤول. راجع وثائق Docker لنظامك.
- **فشل `make shell` على Windows.** شغّله من طرفية يعمل فيها `make` و`docker` معاً، مثل طرفية WSL 2.
- **ظهور `MISSING` لأداة بعد التثبيت المباشر.** أعد تشغيل `scripts/install-native.sh` واقرأ ناتجه. غياب `gcc -m32` يعني أن حزم multilib لم تُثبَّت.
- **لا يجد Ghidra ملفك.** يعمل Ghidra على الجهاز المضيف، فافتح المسار على جهازك (مثلاً `~/asm-reversing-lab/exercises/01-signal-flare/bin/`) وليس `/lab/...`.
- **التعديل داخل المختبر وعلى الجهاز المضيف في آن واحد.** اختر محرراً واحداً ومكاناً واحداً. مجلد المستودع مشترك فيراه الطرفان، لكن محررَين قد يكتب أحدهما فوق الآخر.

## الخلاصة

- شغّل الدورة في مختبر Docker (`make shell`) أو على تثبيت مباشر لـ Ubuntu أو Debian.
- الأمر `make run` في مجلد `examples` لهذه الوحدة يثبت أن المجمّع والرابط والأدوات تعمل.
- يُثبَّت Ghidra على جهازك المضيف ويفتح الملفات من مجلد المستودع.
- لكل تمرين جزء Reverse (علم) وجزء Assemble (شيفرة تفحصها الاختبارات).
- يحتوي `solutions/` على كشف للحلول؛ استخدم `HINTS.md` أولاً.
