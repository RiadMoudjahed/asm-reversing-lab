# 06. الشروط والتفرعات والحلقات

الوقت: نحو ساعتين. المتطلبات السابقة: [05. الحساب والعمليات المنطقية](../05-arithmetic-and-logic/README.ar.md)

## لماذا هذا مهم

ليس في لغة التجميع `if` ولا `while` ولا `for`. كل قرار هو مقارنة تضبط الرايات، تليها قفزة تقرؤها. وحين تستطيع كتابة هذه الأنماط يدوياً، تستطيع التعرف عليها في الشيفرة المترجمة واستعادة شروط البرنامج وحدوده وبنية حلقاته دون مصدر. والخطأ الأكثر شيوعاً، وهو اختيار قفزة بإشارة حيث الشيفرة بلا إشارة، هو أيضاً من أكثر حالات سوء القراءة شيوعاً في الهندسة العكسية.

## المفاهيم

### المقارنة دون تغيير أي شيء

| التعليمة | ما تحسبه | ما تحتفظ به |
|---|---|---|
| `cmp a, b` | `a - b` | الرايات فقط |
| `test a, b` | `a AND b` | الرايات فقط |

`cmp` طرح تُرمى نتيجته. و`test` هي `and` تُرمى نتيجتها. `test rax, rax` هي الطريقة المعتادة للسؤال عما إذا كانت `rax` صفراً أو سالبة، لأن نتيجة `rax AND rax` هي `rax` نفسها.

### القفزات الشرطية

تقفز `jmp label` دائماً. أما القفزة الشرطية فتقفز فقط حين يتحقق شرطها، وإلا يستمر التنفيذ مع التعليمة التالية. بعد `cmp a, b` تُقرأ أسماء القفزات كمقارنة بين `a` و`b`:

| الشرط | بإشارة | بلا إشارة |
|---|---|---|
| يساوي | `je` (`jz`) | `je` (`jz`) |
| لا يساوي | `jne` (`jnz`) | `jne` (`jnz`) |
| أصغر | `jl` | `jb` ("below") |
| أصغر أو يساوي | `jle` | `jbe` |
| أكبر | `jg` | `ja` ("above") |
| أكبر أو يساوي | `jge` | `jae` |

المساواة لا تعتمد على التفسير؛ أما الترتيب فيعتمد. تقرأ `jl` و`jle` و`jg` و`jge` الرايتين SF وOF (وZF)، وهما تصفان نتيجة بإشارة. وتقرأ `jb` و`jbe` و`ja` و`jae` الراية CF (وZF)، وهما تصفان نتيجة بلا إشارة. شرحت الوحدة 02 السبب: CF هي راية الفيض بلا إشارة وOF هي راية الفيض بإشارة. وبعض القفزات تقرأ راية واحدة: `js` و`jns` (الإشارة)، و`jo` و`jno` (الفيض)، و`jc` و`jnc` (الحمل؛ وهما نفسهما `jb` و`jae`)، و`jp` و`jnp` (التكافؤ).

### ضبط قيمة أو اختيار قيمة دون قفز

| التعليمة | الأثر |
|---|---|
| `setcc r8` | تضبط سجلاً بحجم 8 بت على 1 إن تحقق الشرط وإلا على 0 (`setg` و`setl` و`sete` و`setz` و`setc` وهكذا) |
| `cmovcc r, source` | تنسخ المصدر إلى السجل فقط إن تحقق الشرط (`cmovl` و`cmovge` و`cmovb` وهكذا) |

كلتاهما تقرأ الرايات تماماً كالقفزة الشرطية، ولا تغيّرها أيٌّ منهما. تكتب `setcc` 8 بتات فقط، فيحتفظ باقي السجل بقيمته القديمة؛ فصفّر السجل أولاً، وافعل ذلك قبل المقارنة لأن `xor` يغيّر الرايات. تتجنب هاتان التعليمتان التفرع، وهو ما تفضله المترجمات في الشروط القصيرة.

### بناء الهياكل المعتادة

**if / else.** اختبر، واقفز فوق الكتلة التي تريد تخطيها، واقفز فوق جزء else في نهاية الكتلة الأولى:

</div>

```nasm-fragment
    cmp     rdi, rsi
    jle     .else               ; condition false: go to the else part
    ; ... then part ...
    jmp     .end
.else:
    ; ... else part ...
.end:
```

<div dir="rtl">

**while.** الاختبار أولاً، لذا قد لا يُنفَّذ الجسم أبداً:

</div>

```nasm-fragment
.while:
    cmp     rcx, rdi
    jg      .done               ; condition false: leave the loop
    ; ... body ...
    jmp     .while
.done:
```

<div dir="rtl">

**do-while.** الاختبار أخيراً، لذا يُنفَّذ الجسم مرة واحدة على الأقل. هذا هو الشكل المناسب لعدّ أرقام عدد، لأن للعدد 0 رقماً واحداً:

</div>

```nasm-fragment
.again:
    ; ... body ...
    test    rax, rax
    jnz     .again              ; condition true: go around again
```

<div dir="rtl">

**for.** تهيئة واختبار وخطوة، وهي حلقة while تقع خطوتها في نهاية الجسم. النسخ الكاملة من كل ذلك موجودة في [06_control.asm](examples/06_control.asm).

### التعليمة `loop`

تطرح `loop label` الواحد من `rcx` وتقفز إن لم تكن النتيجة صفراً. تبدو مريحة، لكنها على معظم المعالجات أبطأ من `dec rcx` يليها `jnz`، ولا تُصدرها المترجمات. وفيها فخ أيضاً: إن كانت `rcx` تساوي 0 عند الدخول، تطرح أولاً فتحصل على قيمة ضخمة غير صفرية وتعمل 2^64 مرة.

### منظور الهندسة العكسية

لا تعيد المترجمات إليك حلقاتك بالشكل الذي كتبتها به. شغّل `make compiled` في مجلد الأمثلة. هذه مقتطفات حقيقية:

</div>

```text
<max_signed>:     cmp    rsi,rdi
                  mov    rax,rdi
                  cmovge rax,rsi
                  ret

<sum_to>:         test   rdi,rdi
                  jle    <skip>               ; n <= 0: do not enter the loop
                  add    rdi,0x1
                  mov    eax,0x1
                  mov    edx,0x0
                  add    rdx,rax              ; the loop body
                  add    rax,0x1
                  cmp    rax,rdi
                  jne    <body>               ; the test is at the bottom
                  mov    rax,rdx
                  ret

<sum_array>:      test   rsi,rsi
                  jle    <skip>
                  mov    rax,rdi
                  lea    rsi,[rdi+rsi*4]      ; end pointer
                  mov    edx,0x0
                  movsxd rcx,DWORD PTR [rax]  ; the body walks a pointer, no index
                  add    rdx,rcx
                  add    rax,0x4
                  cmp    rax,rsi
                  jne    <body>
```

<div dir="rtl">

ما يمكن قراءته من ذلك:

- **معاملان مقلوبان.** تقارن `max_signed` بين `rsi` و`rdi` وتستخدم `cmovge`: "إن كانت b >= a فخذ b". أُعيدت كتابة الشرط، لكن شرطاً بإشارة (`ge`) يخبرك بأن النوع بإشارة. وتعطي `max_unsigned` الشيفرة نفسها مع `cmovae`.
- **قلب الحلقة.** حارس (`test` و`jle`) يقرر هل ندخل الحلقة أصلاً، ويقع الاختبار الحقيقي في أسفلها مع قفزة إلى الخلف. حلقة فيها قفزة شرطية إلى الخلف هي توقيع `for` و`while` في الشيفرة المحسَّنة.
- **عدّادات أُعيدت كتابتها.** تشغّل `sum_to` عدّاداً حتى `n + 1` مع `jne`، ولا فهرس في `sum_array` إطلاقاً: هي تمشي بمؤشر حتى مؤشر نهاية. الحلقة مكافئة لحلقتك لكنها ليست مطابقة لها.
- **القفزة تخبرك بالنوع.** `jl` أو `jg` تعني بإشارة؛ و`jb` أو `ja` تعني بلا إشارة.

```bash
cd modules/06-conditions-and-loops/examples

```

<div dir="rtl">

الناتج المتوقع:

</div>

```text
max_signed(-1, 1)        = 1
max_unsigned(-1, 1)      = 18446744073709551615
sign_of(-7), (0), (12)   = -1 0 1
sign_branchless same     = -1 0 1
sum_to(10), sum_to(0)    = 55 0
count_digits(0), (9), (12345) = 1 1 5
sum_array({4,-9,20,1}, 4) = 16
is_power_of_two(64), (96), (0) = 1 0 0
```

<div dir="rtl">

يقارن السطران الأولان البتات نفسها، -1 و1، ويعطيان إجابتين مختلفتين: بإشارة تكون -1 أصغر؛ وبلا إشارة تكون -1 أكبر قيمة ممكنة. هذا هو الفرق بين `cmovl` و`cmovb`.

ثم غيّر شيئاً وتوقّع النتيجة قبل إعادة البناء:

1. في `sum_to`، غيّر `jg .done` إلى `jge .done`. ماذا تعيد `sum_to(10)`؟
2. في `max_unsigned`، غيّر `cmovb` إلى `cmovl`. أي استدعاء تتغير إجابته؟

## أخطاء شائعة

- **قفزة بإشارة على بيانات بلا إشارة، أو العكس.** تسيء `jl` التصرف مع طول بلا إشارة حالما يُضبط البت الأعلى. حدّد النوع أولاً ثم اختر `jl` أو `jb`.
- **ترتيب معاملي `cmp`.** `cmp a, b` يليها `jg` تقفز حين تكون `a` أكبر من `b`. وقراءتها بالعكس تعطي الشرط المعاكس.
- **تغيير الرايات بين المقارنة والقفزة.** `add` أو `xor` بينهما تستبدل الرايات. أما `mov` و`lea` فآمنتان.
- **تصفير سجل بعد المقارنة.** `xor eax, eax` بين `cmp` و`setg al` تدمّر الرايات. صفّر أولاً ثم قارن.
- **خطأ بمقدار واحد.** تختلف `jg` و`jge` بدورة واحدة من الحلقة. اختبر القيمة الأولى والأخيرة.
- **نسيان الخطوة.** حلقة لا تزيد عدّادها لا تنتهي أبداً.
- **`loop` مع `rcx` تساوي 0.** تعمل 2^64 مرة.

## الخلاصة

- تضبط `cmp` و`test` الرايات وتتجاهلان النتيجة؛ وتقرأ القفزات الشرطية و`setcc` و`cmovcc` الرايات.
- المقارنات بإشارة تستخدم `jl` و`jle` و`jg` و`jge`؛ وتلك بلا إشارة تستخدم `jb` و`jbe` و`ja` و`jae`؛ والمساواة واحدة لكليهما.
- `if` و`while` و`do-while` و`for` كلها مقارنة وقفزة؛ وموضع الاختبار يحدد كم مرة يُنفَّذ الجسم.
- تضع المترجمات الاختبار في أسفل الحلقات، وتعيد كتابة العدّادات إلى مؤشرات، وتستبدل التفرعات القصيرة بـ `cmov` أو `setcc`.
- شرط القفزة في الشيفرة المترجمة يخبرك إن كان النوع الأصلي بإشارة أم بلا إشارة.
