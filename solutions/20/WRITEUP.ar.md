# شرح الحل: التمرين 20. المشروع الختامي: Tiny VM

العلم هو `ARL{tinyvm_20_41_24}`: للآلة 20 رمز عملية صالحاً، و`call` هو بايت رمز العملية 0x29 (41 بالنظام العشري)، وفي برنامج المثال 24 تعليمة.

## الجزء 1: Reverse

### التهيئة

`tinyvm` صغير ومجرد من الرموز. يُظهر `strings` رسالة الاستخدام والتشخيصين (`halt after %zu steps` و`fault %u at offset %u`) ولا شيء مقروءاً غيرها. يقرأ البرنامج وسيطه ملفاً، ويفحص البايتات الأربعة `TVM1` في البداية، ثم ينفذ حلقة. الحلقة هي المفسّر.

### التوزيع

تقرأ الحلقة بايتاً واحداً من الشيفرة، ثم تجري بحثين في جدولين قبل أن تقفز:

</div>

```text
  401305: movzx  eax,BYTE PTR [rcx]            ; the opcode byte
  401308: movzx  eax,BYTE PTR [rax+0x402160]   ; first table: 256 bytes
  40130f: test   al,al
  401311: je     401403                        ; 0: not an instruction
  401317: movzx  edx,al
  40131a: movzx  edx,BYTE PTR [rdx+0x402130]   ; second table: one byte per instruction
  401321: add    edx,esi                       ; position + length
  401325: cmp    rbx,rsi                       ; against the length of the code
  401328: jb     4013fc                        ; the instruction does not fit
  40132e: mov    DWORD PTR [rsp+0x20],edx      ; new program counter
  401332: cmp    al,0x14
  401334: ja     4012d9
  401336: movzx  eax,al
  401339: jmp    QWORD PTR [rax*8+0x402080]    ; third table: 21 code addresses
```

<div dir="rtl">

ثلاثة جداول إذن:

- الجدول عند 0x402160 فيه 256 بايتاً ومدخل غير صفري في 20 موضعاً بالضبط. هذه المواضع هي رموز العمليات الصالحة، فـ `N` يساوي 20. والمدخل فهرس صغير من 1 إلى 20.
- الجدول عند 0x402130 مفهرس بذلك الفهرس ويعطي طول التعليمة: 4 لتعليمة واحدة، و3 لأربع، و1 لاثنتين، و2 للثلاث عشرة الباقية.
- الجدول عند 0x402080 يحمل 21 عنوان شيفرة، واحداً لكل فهرس (الفهرس 0 يعود إلى رأس الحلقة). المقارنة مع 0x14 هي فحص الحد.

يُخزَّن عداد البرنامج عند `[rsp+0x20]` ويُحدَّث قبل تشغيل الروتين: هذا هو الاصطلاح وراء روتينات الجزء 2. والحالة بنية على المكدس: السجلات الثمانية ابتداءً من `[rsp]`، ثم عداد البرنامج (0x20)، وراية الصفر (0x24)، وراية الحمل (0x28)، ورمز العطل (0x2c)، ومؤشر التوقف (0x30)، وعمق مكدس الاستدعاءات (0x34)، وعناوين الرجوع الستة عشر (0x38)، و256 بايتاً من الذاكرة (0x58).

### روتينات المعالجة

كل عنوان من العناوين العشرين هو شيفرة تعليمة. وقراءتها تعطي السلوك؛ ثلاثة أمثلة:

</div>

```text
; index 3
  401448: movzx  edx,BYTE PTR [rcx+0x1]        ; the byte after the opcode
  40144c: mov    ecx,edx
  40144e: shr    cl,0x4
  401451: and    ecx,0x7                       ; first register: high nibble, modulo 8
  401454: mov    eax,DWORD PTR [rsp+rcx*4]
  401457: and    edx,0x7                       ; second register: low nibble, modulo 8
  40145a: mov    edx,DWORD PTR [rsp+rdx*4]
  40145d: lea    esi,[rax+rdx*1]
  401460: mov    DWORD PTR [rsp+rcx*4],esi     ; r[a] = r[a] + r[b]
  401463: mov    eax,eax
  401465: mov    edx,edx
  401467: add    rax,rdx                       ; the sum again, in 64 bits
  40146a: shr    rax,0x20
  40146e: mov    DWORD PTR [rsp+0x28],eax      ; carry flag = carry out
  401472: test   esi,esi
  401474: sete   al
  401477: movzx  eax,al
  40147a: mov    DWORD PTR [rsp+0x24],eax      ; zero flag = result is 0
  40147e: jmp    4012d9
```

<div dir="rtl">

هذه `add`: تضبط الرايتين. وتُقرأ روتينات `sub` و`xor` وغيرها بالطريقة نفسها. وتفاصيل الأمر في روتين الإزاحة:

</div>

```text
; index 8
  401550: movzx  eax,BYTE PTR [rcx+0x1]
  401554: mov    esi,eax
  401556: and    esi,0xf                       ; the count: the whole low nibble
  401559: mov    edi,eax
  40155b: and    edi,0xf
  40155e: je     4012d9                        ; count 0: nothing changes, flags included
  401564: shr    al,0x4
  401567: and    eax,0x7                       ; the register
  40156a: mov    edx,DWORD PTR [rsp+rax*4]
  40156d: mov    ecx,0x20
  401572: sub    ecx,edi                       ; 32 - count
  401574: mov    edi,edx
  401576: shr    edi,cl                        ; value >> (32 - count)
  401578: mov    ecx,edi
  40157a: and    ecx,0x1
  40157d: mov    DWORD PTR [rsp+0x28],ecx      ; carry flag = last bit shifted out at the top
  401581: mov    ecx,esi
  401583: shl    edx,cl
  401585: mov    DWORD PTR [rsp+rax*4],edx
  401588: test   edx,edx
  40158a: sete   al
  40158d: movzx  eax,al
  401590: mov    DWORD PTR [rsp+0x24],eax      ; zero flag
  401594: jmp    4012d9
```

<div dir="rtl">

العداد هو النبل الأدنى كله (0 إلى 15)، بينما يستخدم السجل ثلاثة بتات من النبل الأعلى. العداد صفر يعود قبل أن تُمس أي راية. و`shr` صورتها المرآتية، مع أخذ راية الحمل من البت `count - 1`.

</div>

```text
; index 14 (call)
  401666: mov    eax,DWORD PTR [rsp+0x34]      ; depth
  40166a: cmp    eax,0x10
  40166d: je     401693                        ; full: fault 3
  40166f: lea    esi,[rax+0x1]
  401672: mov    DWORD PTR [rsp+0x34],esi      ; depth + 1
  401676: mov    eax,eax
  401678: mov    WORD PTR [rsp+rax*2+0x38],dx  ; push the program counter (already advanced)
  40167d: movzx  eax,BYTE PTR [rcx+0x2]
  401681: shl    eax,0x8
  401684: movzx  edx,BYTE PTR [rcx+0x1]
  401688: or     eax,edx                       ; target: byte 1 + 256 * byte 2 (low byte first)
  40168a: mov    DWORD PTR [rsp+0x20],eax
  40168e: jmp    4012d9
  401693: mov    DWORD PTR [rsp+0x2c],0x3      ; fault code 3
  40169b: jmp    4016c4                        ; then halt
```

### مجموعة التعليمات

بجمع الروتينات العشرين تنتج المواصفات (الأسماء من التمرين):

| رمز العملية | الاسم | الطول | الأثر |
|---|---|---|---|
| 0x5b | `movi` | 4 | `r[a] = number` (العدد من 16 بتاً في البايتين 2 و3، البايت الأدنى أولاً)؛ الرايات دون تغيير |
| 0xc2 | `mov` | 2 | `r[a] = r[b]`؛ الرايات دون تغيير |
| 0x17 | `add` | 2 | `r[a] += r[b]`؛ `cf` = الحمل الخارج، `zf` = الناتج 0 |
| 0x8e | `sub` | 2 | `r[a] -= r[b]`؛ `cf` = a < b بلا إشارة، `zf` = الناتج 0 |
| 0x34 | `mul` | 2 | `r[a] *= r[b]` (الـ 32 بتاً الأدنى)؛ `cf` = 0، `zf` = الناتج 0 |
| 0xe9 | `xor` | 2 | `r[a] ^= r[b]`؛ `cf` = 0، `zf` = الناتج 0 |
| 0x61 | `and` | 2 | `r[a] &= r[b]`؛ `cf` = 0، `zf` = الناتج 0 |
| 0xa5 | `shl` | 2 | إزاحة يساراً بالنبل الأدنى؛ العداد 0 لا يغيّر شيئاً؛ `cf` = آخر بت يخرج من الأعلى، `zf` = الناتج 0 |
| 0x0d | `shr` | 2 | إزاحة يميناً بالنبل الأدنى؛ العداد 0 لا يغيّر شيئاً؛ `cf` = آخر بت يخرج من الأسفل، `zf` = الناتج 0 |
| 0x7a | `cmp` | 2 | الرايات كما في `sub`، ولا يُخزَّن شيء |
| 0xf3 | `jmp` | 3 | `pc` = الهدف من 16 بتاً في البايتين 1 و2 |
| 0x42 | `jz` | 3 | قفز إذا كانت `zf` تساوي 1 |
| 0xb8 | `jnz` | 3 | قفز إذا كانت `zf` تساوي 0 |
| 0x29 | `call` | 3 | دفع `pc` (المتقدم فعلاً) ثم القفز؛ عطل 3 وتوقف إذا كان في المكدس 16 عنواناً |
| 0xd6 | `ret` | 1 | سحب `pc`؛ عطل 2 وتوقف إذا كان المكدس فارغاً |
| 0x93 | `ldb` | 2 | `r[a] = mem[r[b] & 255]` |
| 0x6c | `stb` | 2 | `mem[r[a] & 255] = r[b] & 255` |
| 0xfc | `out` | 2 | طباعة `r[a]` عدداً عشرياً بلا إشارة وسطراً جديداً |
| 0x05 | `outc` | 2 | طباعة المحرف `r[a] & 255` |
| 0xa0 | `halt` | 1 | توقف |

في كل تعليمة لها بايت سجلات يكون السجل الأول هو النبل الأعلى والثاني هو النبل الأدنى، وكل منهما بالقياس 8؛ وتُخزَّن الأعداد من 16 بتاً بالبايت الأدنى أولاً. ويحمل `isa.json` في `solutions/20/` هذا الجدول بصيغة التمرين. الأعطال 1 (رمز عملية غير صالح) و5 (تجاوز النهاية أو خطوات كثيرة) و6 (تعليمة مقطوعة بنهاية الشيفرة) تأتي من حلقة المفسّر وليست من الروتينات.

## الجزء 2: Assemble

### روتينات المعالجة

روتينات المرجع في `solutions/20/solution.asm`. تبدأ كلها بتفكيك بايت السجلات. الفحوص المهمة والأخطاء التي تضيّع الوقت:

- **الأقنعة.** حقول السجلات نبلات من 0 إلى 15، تؤخذ بالقياس 8 (`and 7`). وعداد الإزاحة هو النبل الأدنى كله (`and 15`) ولا يُختزل.
- **أي الرايات.** يمسح `mul` راية الحمل؛ ويضبط `shl` و`shr` راية الحمل من آخر بت يخرج ولا يفعلان شيئاً البتة مع العداد صفر. والروتين الذي يمسح الرايات أو يعيد حسابها عند العداد صفر يفشل في الاختبارات التي تبدأ بقيم رايات عشوائية.
- **حمل `shl`.** هو البت `32 - count` من القيمة القديمة، وليس البت نفسه في `shr` (البت `count - 1`).
- **`cmp`.** راية الحمل مقارنة بلا إشارة؛ والمقارنة الموسومة تفشل حين يكون البت الأعلى لإحدى القيمتين مضبوطاً.
- **`call` و`ret`.** العنوان المدفوع هو عداد البرنامج المتقدم فعلاً. وحالات العطل لا تغيّر إلا رمز العطل ومؤشر التوقف.
- **`ldb` و`stb`.** يُستخدم البايت الأدنى فقط من سجل العنوان، ويخزّن `stb` البايت الأدنى فقط من القيمة.
- **حفظ السجلات.** تستخدم الروتينات سجلات يجوز للدالة تغييرها فقط، فلا شيء يُحفظ.

### البرنامج

برنامج المرجع هو `solutions/20/program.tvs`. تخزّن حلقة العدد الحالي في العنوان الذي يعطيه عداد وتقدّم الزوج؛ ويعدّ روتين فرعي نزولاً من 12 ويحمّل كل بايت ويطبعه. والسجل الذي لا يُضبط أبداً يخدم صفراً لاختبار نهاية الحلقة. ويعمل في 165 خطوة.

</div>

```text
fill:   stb  [r2], r0
        mov  r4, r0
        add  r4, r1
        mov  r0, r1
        mov  r1, r4
        add  r2, r3
        cmp  r2, r5
        jnz  fill
```

## أخطاء تضيّع الوقت

- أخذ حقول السجلات بترتيب خاطئ أو من النبل الخاطئ. `register_a` الخاطئ يكشفه فحص `isa.json` والبرنامج، لأن المُجمِّع يضع السجلات بحسب ملاحظاتك.
- قراءة `sub` بمعاملات معكوسة. السجل الأول هو الهدف والمعامل الأيسر.
- إغفال أن بعض التعليمات تترك الرايات دون مساس (`movi` و`mov` و`ldb` و`stb`).
- حساب مقطع البيانات أو الترويسة في عدد التعليمات.
- كتابة روتين يعمل للسجلات 0 إلى 7 ويفشل للنبلات 8 إلى 15 التي تلتف.
