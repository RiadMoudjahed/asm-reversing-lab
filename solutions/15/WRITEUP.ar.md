# شرح الحل: التمرين 15. المخزون المترابط

العلم هو `ARL{inventory_32_16_20_24_0_4}`: حجم العقدة 32 بايتاً، والمفتاح عند الإزاحة 16، وعداد المرور عند الإزاحة 20، وعداد التكرار عند الإزاحة 24، ومؤشر المفاتيح الأكبر عند الإزاحة 0، ويُظهر عداد التكرار ذو 16 بتاً القيمة 4 بعد 65540 إدراجاً للمفتاح نفسه.

## الجزء 1: Reverse

### حلقة البحث

أقصر دالة تعبر البنية هي دالة البحث. الملف التنفيذي مجرَّد من الرموز فلا اسم لها؛ وهي الدالة التي تأخذ مؤشراً ومفتاحاً وتنتهي بحلقة بلا استدعاءات:

</div>

```text
401176:  mov    rax,rdi
401179:  test   rdi,rdi
40117c:  jne    401188
40117e:  ret
40117f:  mov    rax,QWORD PTR [rax+0x8]      ; lesser link
401183:  test   rax,rax
401186:  je     401196
401188:  mov    edx,DWORD PTR [rax+0x10]     ; key
40118b:  cmp    esi,edx
40118d:  je     401196                       ; found
40118f:  jle    40117f                       ; key <= node key: follow offset 8
401191:  mov    rax,QWORD PTR [rax]          ; key > node key: follow offset 0
401194:  jmp    401183
401196:  ret
```

<div dir="rtl">

تقرأ الحلقة المفتاح عند الإزاحة 16 قيمةً من 32 بتاً وتقارنه بـ `esi` بالتعليمة `jle`، وهي مقارنة بإشارة. تنهي المفاتيح المتساوية الحلقة. ويتبع المفتاح الأصغر أو المساوي المؤشر عند الإزاحة 8، ويتبع المفتاح الأكبر المؤشر عند الإزاحة 0. إذن `G` يساوي 0 و`K` يساوي 16. والبنية شجرة بحث ثنائية، والمؤشران هما رابطا "الأكبر" و"الأصغر".

### الإدراج

تحجز دالة الإدراج الذاكرة وتعدّ:

</div>

```text
4011ac:  add    DWORD PTR [rdx+0x14],0x1     ; pass counter
4011b0:  mov    ecx,DWORD PTR [rdx+0x10]
4011b3:  cmp    ebp,ecx
4011b5:  je     4011f5                       ; same key
4011b7:  lea    rbx,[rdx+0x8]                ; link = &node->lesser
4011bb:  cmovg  rbx,rdx                      ; if key > node key: link = &node->greater (offset 0)
4011bf:  mov    rdx,QWORD PTR [rbx]          ; node behind the link
4011c2:  test   rdx,rdx
4011c5:  jne    4011ac
4011c7:  mov    esi,0x20                     ; calloc(1, 32)
4011cc:  mov    edi,0x1
4011d1:  call   calloc
4011d6:  mov    DWORD PTR [rax+0x10],ebp     ; key
4011d9:  mov    DWORD PTR [rax+0x14],0x1     ; pass counter starts at 1
4011e0:  mov    WORD PTR [rax+0x18],0x1      ; duplicate counter starts at 1
4011e6:  mov    QWORD PTR [rbx],rax          ; store into the link
...
4011f5:  add    WORD PTR [rdx+0x18],0x1      ; same key: duplicate counter
```

<div dir="rtl">

تنتج عن هذا الإدراج حقائق عدة:

- **الحجم.** يطلب الحجز كتلة من 32 بايتاً، إذن `S` يساوي 32. وينتهي آخر حقل عند الإزاحة 26، فللكتلة 6 بايتات حشو. ويأتي الحجم من الاستدعاء لا من الحقول.
- **عداد المرور.** تُنفَّذ التعليمة عند `4011ac` قبل المقارنة لكل عقدة يزورها العبور، بما فيها العقدة ذات المفتاح المساوي. وهو حقل من 32 بتاً عند الإزاحة 20، إذن `T` يساوي 20.
- **عداد التكرار.** تُنفَّذ التعليمة عند `4011f5` فقط حين يوجد المفتاح. وهي تجمع على `WORD PTR`: عرض الحقل 16 بتاً وموضعه عند الإزاحة 24، إذن `C` يساوي 24.
- **الرابط.** تحتفظ الشيفرة في `rbx` بعنوان الرابط الذي ستتبعه لا بالعقدة. والرابط الأول هو خانة المكدس التي تحوي الجذر (`lea rbx,[rsp+0x8]` عند `4011ff`). وحين يحوي الرابط 0 تُخزَّن العقدة الجديدة فيه. وتعالج قطعة شيفرة واحدة البنية الفارغة والورقة الجديدة على أي عمق.
- **العقد الجديدة.** يبدأ العدادان عند 1 ويبقى رابطا الابنين عند 0، لأن `calloc` يصفّر الكتلة.

### الالتفاف

لأن عداد التكرار بعرض 16 بتاً فإنه يلتف بعد 65535. يطبع الأمر `f 7` عداد التكرار أولاً ثم عداد المرور. وبعد 65540 إدراجاً للمفتاح 7 يكون العدد الأول `65540 mod 65536` أي 4، والثاني 65540:

</div>

```text
$ for i in $(seq 65540); do echo 'i 7'; done | { cat; echo 'f 7'; } | bin/inventory | tail -1
4 65540
```

<div dir="rtl">

إذن `W` يساوي 4. وعداد المرور بعرض 32 بتاً فلا يلتف هنا.

## الجزء 2: Assemble

الحل المرجعي هو `solution.asm`. والنقاط المهمة:

- **التخطيط.** الإزاحة 0 رابط الأكبر، والإزاحة 8 رابط الأصغر، والإزاحة 16 المفتاح، والإزاحة 20 عداد المرور، والإزاحة 24 عداد التكرار. وحجم العقدة 32 بايتاً، وتبقى البايتات من 26 إلى 31 أصفاراً.
- **`inv_find`.** لا تحتاج إلى مكدس ولا إلى سجلات محفوظة. في كل دورة تفحص هل الرابط فارغ، وتقارن المفتاح بـ `cmp esi, [rdi + 16]`، وتنتهي عند التساوي. وتبقى رايات هذا `cmp` صالحة حين يختار `cmovle` الرابط الأصغر بدل الأكبر، لأن عمليات التحميل بينهما لا تغيّر الرايات.
- **`inv_insert`.** تحتفظ بعنوان الرابط في `r13`. والرابط الأول خانة مكدس تحوي الجذر، فتحجز الدالة 16 بايتاً. وتُبقي ثلاث عمليات push والـ 16 بايتاً `rsp` محاذياً لاستدعاء `inv_alloc`. وعند كل عقدة تزيد عداد المرور بـ `inc` من 32 بتاً وتقارن المفتاح، ثم إما تزيد عداد التكرار بـ `inc` من 16 بتاً أو تختار الرابط التالي بـ `lea` و`cmovg`.
- **عقدة جديدة.** تعيد `inv_alloc` ذاكرة مصفّرة. تخزّن الشيفرة المفتاح وتجعل العدادين 1 وتخزّن مؤشر العقدة في الرابط. وتعيد الدالة قيمة خانة الجذر التي لا تتغير إلا إذا كانت البنية فارغة.
- **السجلات.** تُحفظ `rbx` و`r12` و`r13` وتُستعاد بترتيب عكسي.

## أخطاء تضيّع الوقت

- **استخدام زيادة من 32 بتاً لعداد التكرار.** تبقى القيمة التي تعرضها المكتبة هي نفسها حتى يلتف العداد، لكن الزيادة تكتب أيضاً في الحشو بعد الحقل. ويبلّغ المدقق عن `overrun`.
- **تخطي عداد المرور عند العقدة المطابقة.** تكون مجاميع كل العقد على مسار مفتاح مكرر أقل بواحد.
- **مقارنة المفاتيح قيماً بلا إشارة.** تذهب المفاتيح السالبة والقيم القصوى إلى الجهة الخطأ. ويُظهر نص الشجرة المفاتيح في أماكن خاطئة.
- **استدعاء `inv_alloc` لمفتاح موجود أصلاً.** تبدو الشجرة صحيحة لكن المدقق يبلّغ عن `alloc`.
- **الاحتفاظ بالجذر في سجل.** يجب أن يكون للرابط عنوان؛ ويمكن أن يشير `r13` إلى خانة مكدس أو إلى حقل في عقدة، لا إلى سجل.
- **مكدس غير محاذٍ عند الاستدعاء.** قد ينجح الاستدعاء مصادفة؛ ويبلّغ المدقق عن `align`.
